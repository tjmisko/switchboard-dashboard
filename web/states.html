Field Guide

Reading the Status Colors

Every coding-agent session gets one colored chip on the bar, meant to be read from across the room. Green is work running. Orange is a session waiting on a new prompt. Red is your decision blocking work.

The color is computed, not guessed — a total function over everything Switchboard believes about the session. Sections 1–4 are the operator's path; the reference half is the model underneath.

    Timeline Lanes

    Every bar on the dashboard carries one of six statuses — the wire vocabulary of the provider contract, which every source emits.

    Dormant is the one worth internalizing: the session handed off, and the green underneath belongs to a subagent. Dormant time is delegated time, which is why the dashboard counts it as leverage.

    Sessions & Writers

    A session is 1 + N writers: the main thread plus every subagent in flight, sharing one process, one log, one chip. Each can block on its own permission prompt.

    • Green can mean the main thread stopped a minute ago while three subagents run on.
    • Red can belong to a subagent you never started. Same keystroke to clear, and it unblocks work you cannot see.

    Only the per-writer machine in §7 has memory. The chip is a pure function of the writer → state map, memoryless by construction: a latch in the color layer is what stale red and false green are made of.

    Color Resolution

    Six rungs, first match wins. Nothing here knows a main thread from a subagent.

      Why Red Outranks Green

      The rungs rank by what it costs you to leave a session alone.

      Red — a cheap decision holding up expensive work

      Approval or a one-line answer, with a chain of unattended work behind it. The best return on a second of your time.

      Clear It Now

      Green — work is happening

      Asks nothing of you. Interrupting costs more than it returns.

      Leave It

      Orange — the session wants real input

      A prompt, a review, a decision. Nothing here proceeds without you, so leaving it costs only delay — batching orange to protect a block of focus is often right.

      Known Inaccuracies

      The daemon does not implement all of the model below. The one that will bite you: a red can clear before you answered — measured at 5s into a prompt that stayed unanswered for another 3m07s. Your terminal is the source of truth.

      Both divergences and four unimplemented transitions are catalogued in §8, with cell coordinates and rule ids.

      Writer States

      Seven states. Each is a claim about a single writer, never about the session.

      The Central Ambiguity

      ToolInFlight unmatched tool_use in the tail
      Identical on Disk
      Blocked unmatched tool_use in the tail

      A tool merely running and one waiting on your approval leave the same mark in the log. Only a permission notification separates them, and it fires once, on the edge. This is the general case: on Codex a gated call is byte-identical to a running one, with no recovery from the file at all. Three invariants follow:

      1. Blocked cannot be rebuilt by reading files, so it is the one state that must survive a daemon restart.
      2. The log can only ever say “ToolInFlight or Blocked.” It can falsify a belief; it can never establish one.
      3. Leaving Blocked needs the negation of that mark — every dispatched tool matched. Anything weaker cannot tell the twins apart, so it cannot prove your prompt was answered. The shipped daemon breaks this one (§8).

      Monitoring & Evidence

      Switchboard observes; it never asks an agent how it is doing. Three sources, and each one bounds what its evidence can prove. The shape is the adapter contract; what fills it is per agent, and two agent kinds ship today.

      So a provider that announces nothing about permission can never paint red — no log distinguishes a gated tool from a running one. Of the writer-driven colors it reaches only green, orange and gray; suspended and hidden still work, because those rungs sit above the machine and read the process rather than the agent. That is a tier limit rather than a bug: the contract also accepts a source with no status concept at all, as one working interval spanning the lifetime.

      The thirteen kinds the Claude adapter supplies — hover for meaning; the two marked key are load-bearing. Codex announces the same events but never persists approvals, so it cannot supply the sound exit from Blocked and falls back to the cap.

      Universal Rules

      • Gone → Dead — the process exited, or the subagent was force-closed.
      • SessionRotated → Unknown — a context reset or fork changed the session id under the same pid, retiring every prompt recorded against the old one.

      The State Machine

      Six live states × 11 kinds of evidence — 66 cells, no defaults. An unlisted cell throws rather than guessing. Evidence is attributed to a writer by the caller, so cross-writer bugs live outside the machine.
