Field Guide

A chip is a reduction of a fresh agent graph.

The switchable unit is an OS root process, identified by (pid, started_at). A trusted hook binds its exact Claude or Codex session ID. Provider-specific state machines fuse edges with re-readable evidence, then publish one bounded root/descendant graph for the shared reducer.

The chip is intentionally lossy. Provider evidence and graph detail remain available below it; process death and suspension are separate OS facts.

    Mental model

    (pid, started_at) → exact provider root ID → provider state → fresh Observation → normalized tree → { Reduce → chip; graph diff → history edges }
    • Only discovered root processes are switchable. Descendants are provider identities with explicit parentage; no shared-process or shared-log assumption.
    • Binding never uses cwd, title, timestamps, or “most recent session” heuristics.
    • Slow provider I/O runs outside the state lock; generations fence late results.
    • The graph is provider-owned. The reducer is provider-neutral and memoryless except for Summary.Since.

    The actual state machines

    There is no single shared flat per-writer FSM on main. Each provider runs an extended state machine with parallel regions and keyed state. Hooks apply edges; files or app-server snapshots reconcile levels. The graph is the immutable handoff, not the memory.

    ProviderState = control regions × map[node] × map[request] × timers then Project(ProviderState) → Observation then Reduce(Observation) → Summary

    An outer OS machine remains separate: running / suspended / gone. Suspension overlays the chip; process death removes the root.

      Graph contract

      Every projected node has three independent axes. This product state replaces the old one-of-seven writer enum; provider machines decide how evidence reaches each axis.

      runtime

      attention

      Structure

      One exact root, unique IDs, explicit parent chains, no cycles. Normalization emits deterministic root-first depth-first order.

      Positive child liveness

      !terminal && (attention || runtime∈{active,idle} || lifecycle∈{pending,running}). The root is always included for attention.

      Zero-credit topology

      A child that is only unknown/not_loaded is visible but neither live nor delegating.

      Terminal wins

      completed, interrupted, errored, shutdown, and not_found suppress stale child runtime and attention.

      Completeness

      Only a Complete snapshot makes omission authoritative as not_found. Partial omission retains prior topology; the reducer itself ignores the flag.

      Claude vs. Codex

      They share the graph contract, not an evidence pipeline.

      Claude hooks

      SessionStart, UserPromptSubmit, PostToolUse, PermissionRequest, Stop, SubagentStart, SubagentStop.

      Codex hooks

      SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PermissionRequest, Stop, SubagentStart, SubagentStop.

      Codex observation

      The interactive client remains ordinary codex. A separate disposable app-server has a read-only request allowlist: initialize, thread/read, thread/list, thread/turns/list.

      Authority and degradation

      Source is not a reducer confidence score. Codex orders exact event time first; otherwise the coordinator resolves freshness, source rank, and observation time. Provider ownership and exact hook overlays add narrower rules.
